## 做什么

三件事，同一面：**让第一次用这个页面的人看得懂、点得对**。

1. 把「人自己的动作」补回办公室界面：**回答并恢复、放行、重新打开、取消这条活**，
   以及方案卡上的**驳回方案**。
2. 把界面的说法从平台内部名换成**人话**（状态、按钮、提示、窗口名、次数说法）。
3. 加一个独立窗口「各个窗口都说了什么」：按窗口摊开每条活最近一次的 CLI 原话。

## 为什么

### 一、按钮在迁移里丢了

旧的人操作面（`frontend/`，已随 `f1f9b7e` 删除）里有这些按钮：`MVP-UI-004`
明写"管理链与 §18 五决策动词接入三栏壳"，`frontend/src/components/TaskPane.vue`
里能读到 `RESUME_STATES` / `REOPEN_STATES` / `CANCEL_STATES` 与五个动作的分支。
迁到 Agent Office 时**整批只剩 API 与 CLI，界面上一个按钮都没有**。

后果不是"少几个按钮"，而是**状态成了死路**：

- `awaiting_human` 的任务在等一个人回答（R10 §10 `human.question`），
  而界面上除了发群消息没有别的出口 —— 平台不认群消息，任务就一直等；
- `escalated` 的任务没有放行出口（ADR-033 要求非终态有不依赖 owner 的恢复出口）；
- `abandoned` 的活人不能重开；
- 方案只能批准不能驳回 —— 批准成了"只能点头"。

后端端点一直都在（`/human/resume`、`/human/reopen`、`/human/release`、
`/human/cancel`、`/plans/{id}/reject`），CLI 也有对应命令
（`human-resume` / `human-reopen` / `human-release` / `human-cancel`）；
缺的只是界面。

### 二、字也没人看得懂

做法是**先看画面再改**：把办公室渲染出来（带假数据），逐屏截图，用眼睛看。
第一屏的问题不是「不好看」，是**读不懂**：

- 状态词是平台内部名：`待领取 / 待审 / 待人工 / 等人回答 / 方案漂移`；
- 按钮是平台动作名：`请求再给一次机会（预算豁免）` / `放行回队列` / `批准并派单`；
- 对话框里直接写 `决策行 / attempt / epoch / R10 §8`；
- 窗口显示成 id：`codex-window` 而不是「Codex 窗口」；
- 额度卡显示 `已用 undefined 次`（平台没给这个数时，界面把 undefined 印出来了）；
- 顶栏显示 `g · 已连接正式平台`（群 id）和一个孤零零的「你」。

走查还看出两个真缺陷：

- `hidden` 属性被 `display:grid` 盖掉 → 「顺便再给一次机会」那个勾选框
  **在每一个对话框里都露着**（静态测试全绿，肉眼才看得见）；
- 模态对话框是 `inset:0; margin:auto` 定位的，`height:auto` 会拉满视口 ——
  处置对话框虽有内容，却有 640px 高的一大片空白（要 `fit-content` 才按内容收）。

### 三、想看"他们说了什么"只能一条条点

平台记的是**结果**（谁接了、谁提交了、审没审过），人真正想看的是**窗口自己说的话**：
测试怎么报的错、改了哪些文件、最后写了什么。原来这些只在选中某条活的详情里看得到，
一条一条点。补一个独立窗口 `/outputs.html`（从办公室右栏「看他们说了什么」打开），
按窗口分组摊开。

**每一次尝试都摊开**，不只最近一次：一条活做过三次，这里就摊三次（新的在前），
同一条活的几轮收在一起，不把标题重复三遍。分组的键是**这一次尝试是谁做的**
（attempt 的 owner），不是活现在的主人 —— 改派过之后这两者不是一回事，而"谁当时
说了什么"才是这里要的。

数据一次取回：浏览器只发一个请求（`GET /api/formal/outputs`），网关在服务端并行取
每条活每一次尝试的 `/tasks/{id}/output?attempt_id=…`。attempt_id 是**算出来的**
（`{task_id}.a{attempt_no}`，见 `backend/app/claim/service.py`），所以不用先捞一遍
事件才知道有哪些尝试，直接按 1..attempt_no 枚举即可。

### 四、对着真平台跑一遍,改出来的东西

假数据好看、真数据难看 —— 真跑一遍（真平台 8848 + 真令牌 + 真的群 office-formal-2）
暴露了四个问题，都不是断言能发现的：

1. **平台的 attempt 状态列是旧的**：提交之后就停在 verifying/in_progress 不动了。
   一条已经 merged 的活，它的 attempt 状态还是 verifying —— 按它筛"做完了的"，
   一条都筛不出来。每一轮**真正的结果**在**事件**里（submit_result / abandon / release，
   abandon 还带原因）。所以网关去整群取一次事件（844 条一页装得下），按
   `活|尝试` 建索引，每一轮标出"交上去了 / 放弃了（为什么）/ 放开了"。
2. **筛选要按活的状态**（人理解的那个意思），不是按某一轮的状态。默认改成「全部」，
   另有「做完了的 / 没做成的」。
3. **真实 stdout 常常是一整行超长 JSON**：按行截断等于没截，4000 字直接糊在脸上。
   再加一道按字数的底（1200 字），并写明"前面还有 N 字"。
4. **合入后平台把 owner 清空了**：于是"已完成"的活在列表里写着"没人做（之前是
   OpenCode）"—— 一件做完的事说成没人做。先看状态再说人：做完了 / 没做成 / X 在做。

顺带量了一下真平台的规模并据此改了实现：群里 74 条活、44 次尝试、18 次有话可看。
逐活取事件要 80 个上游请求、3.7 秒；改成整群取一次事件后是 48 个请求、1.1 秒。
页面的自动刷新也从 15 秒改成 60 秒（这是"看历史"的页面，60 秒一轮，想立刻看按「刷新」）。

### 五、给第一次用的人的三件事

真跑之后我列了一份"小白会卡在哪"的清单,先做了最卡人的三件:

1. **大厅里看不到平台上已有的活**。真实平台上那个群有 74 条活,但大厅只有
   「新建项目」「连接工作窗口」,已有的活藏在「恢复最近项目：xxx」那个按钮里 ——
   文案完全没说这是什么。现在大厅多一段「平台上已有的项目」:把平台上的活按
   「项目名 · 」前缀归堆（真实数据下认出 6 个项目），每项一个「打开」，点下去
   直接进那个项目的办公室，并且它会进本机历史（下次还在）。
   空状态里那个按钮也改成说人话的「打开这个项目（已有 N 件事）」。
2. **README 顶上加一节「连上真平台」**：`npm run dev` 起的是**空界面**（本地样例），
   真东西要设 5 个环境变量。现在 README 第一屏就把那 5 行写清楚（可直接复制）、
   说明令牌文件在 `data/` 下且哪个是"人"哪个是"管理员"、以及忘了设会看到什么。
   `office/.env.example` 同步改成可复制的形状。
3. **额度池与「现在能干活的人」默认收起**。它们是给运维看的事实：一屏之内
   「11 个额度来源 · prompt tokens · credits」对第一次用的人只是噪音。现在
   折成一行摘要（"额度池 · 11 个额度来源，已用 26 次"），想看再点。

还没做的（留档）：输出窗口里大半是机器 JSON，真结论常被长文截断吃掉；
平台助手整段仍是术语；「连接工作窗口」那扇门对小白没用（登记机器人是运维的事）。

### 六、从机器日志里抽人话（输出窗口的真问题）

"各个窗口都说了什么"里原本是一屏 JSONL。查了三家 CLI 的输出格式（不是猜，是查过）：

- Claude Code `--output-format stream-json`：每行一个对象，
  `{"type":"assistant","message":{"content":[{"type":"text","text":...}]}}`，
  收尾有 `{"type":"result","result":"<最终结论>"}`；
- Codex `exec --json`：`{"type":"item.completed","item":{"type":"agent_message","text":...}}`
  （老版本叫 assistant_message），命令是 `item.type === "command_execution"`；
- OpenCode：`{"type":"text","part":{"text":...}}`、`{"type":"tool","tool":"shell",...}`。

于是写了 `office/src/cli-transcript.js`：按**字段形状**认（不认 CLI 名字），认不出来
就原样返回，绝不猜。解析放在**网关侧**——一条活的 stdout 在真数据里有 26 KB，
几十条活就是几百 KB，浏览器自己拉再拆会卡死；网关拆完只给"它说了什么 + 它做了
哪些步 + 原文尾巴"，响应从 79 KB 降到 67 KB。

真数据实测：18 次尝试里 15 次抽到了人话（「## 完成报告」「Done. Committed on the
current branch as ...」），页面第一屏就是那篇 Markdown 报告，而不是一堆 JSON。
剩下 3 次是真的没有：一次 stdout 是空的，一次只有 168 条 system 事件，一次只有
工具调用没有文本。

工具步骤也翻成人话：「跑了命令：npm test」「写了文件：commit-msg.txt」
「搜了代码：TODO」——CLI 的工具名（shell/read/write/grep…）认得出就换成人话，
认不出的**只报原名**（挑一个字段来解释它是在猜，猜错比不解释更糟）。

踩到的坑：① OpenCode 的文字在 `part.text` 里、不在顶层——照顶层读会读到 undefined，
什么也抽不出来；② OpenCode 的工具细节也在 `part` 里（`{"type":"tool_use","part":
{"tool":"read","state":{...}}}`），而 Claude Code 把 `input` 放顶层——两处都要找；
③ 网关把 stdout 截成最后 4000 字时第一行必然是**半截 JSON**，所以"坏行不炸"这条
是必须的。

### 七、平台助手的段落标题

11 个标题全是内部名（巡检摘要 / 谁现在能用 / 平台额度池 / 失败与接手 / 方案定稿…），
换成：进度总览 / 谁能干活 / 额度 / 没做成的活 / 等你批准的方案 / 谁干得好 /
要管理员处理的事 / 攒着的事 / 播报 / 等着审的 / 卡住的事。每段下面的说明也重写
成人话。`verify-platform-assistant.mjs` 按标题找段落的断言同步改了——断的是
"这一节只该有人的动作"这件事，不是标题必须长什么样。

### 八、那扇没用的门

「连接工作窗口」是"本机还没登记机器人"时的补救动作，对第一次用的人没用。现在
大厅里直接说明白：「已经有 7 个能干活的了（Claude Code、Codex CLI…）。要加新的，
再点「连接工作窗口」。」一个都没有时才提醒他可能得先登记。

### 九、"像半成品"这一回

用户看了一眼里说"现在的页面看起来还是太粗糙了，就像是那种半成品一样"。对着
真画面一屏一屏看下来，粗的不是配色，是**没做完的痕迹**：

1. **两套设计语言**：大厅是绿色编辑风，办公室是蓝灰工具风，顶栏又是第三种 ——
   一个产品里三种风格，怎么看都像拼的。大厅整份换成办公室那套蓝灰（114 处色值）。
2. **英文装饰词**：`PROJECT DESK / 01`、`HISTORY`、`ON THE PLATFORM`、
   `AGENT OFFICE · 数据版` —— 对第一次用的人是噪音。去掉，位置让给中文标题。
3. **同一个名字出现两遍**：外壳顶栏已经是"Agent Office"，大厅自己又顶了一个
   品牌头；同一件事（历史只在本机）在页脚还说了两遍。删掉重复的那份。
4. **机器名不上屏**：`FD-8665828938c488fd.a1`（attempt id）、`任务编号 FD-…`、
   标题末尾的「（qoder）」、方案卡的**绝对路径**（一整条 D:\… 把卡片撑变形）。
   全部收进 title 或「技术信息」折叠；失败原因 `harness CLI exited 1` 换成
   「窗口的命令退出了（退出码 1）」，**认不出的原样留着**（宁可原样，也不编一个错的说法）。
5. **版式**：两栏之间 78px 的空当 + 页面下半截全空 → 收成 40px、内容居中；
   五个筛选项排成整齐的 3+2；顶栏五个计数从"标签在上、数字悬在下面"改成一枚枚
   徽章（0 不该跟"2 件没做成"一样响）；右栏卡片白底 + 轻影 + 圆角 + 同一行等高，
   卡片标题从 11px 大写英文风改成 13px 的中文标题。
6. **时间说人话**：`更新于 2026/10/19 04:59:31` → `4 天前更新`。
7. **事件列表也不该是机器字段**：`413 | cancel | office-operator` → `10/18 20:20 · 取消了 · 你`。
   事件名的中文表放在 `state-labels.js`（状态词也在一起，两个页面不会各说各话）；
   **不认识的事件名照实显示**（宁可原样，也不编一个错的动作）；事件编号收进 title。
   顺手被版式冒烟抓到一处真回归：时间列放不下完整的 `2026/10/18 20:20:08`，
   1200px 下横向溢出 —— 改成短时间 `10/18 20:20`（完整时间留在 title 里）。

改完再截一次图对比；21 条办公室冒烟全绿。

### 十、"活气"：正在跑的那条活要看得见它在动

用户挑了这一条（"还是有点粗糙"里剩下的真缺口之一）。平台的 `/output` 读的是
worker **正在写的那个日志文件的尾巴** —— 数据本来就是活的，缺的是界面盯着它：

- 列表里正在跑的活带一个**心跳点**（会呼吸的小点）。
- 详情里是「**它现在正在做什么**」，上面写着"刚刚还在动 · 每 4 秒自己更新"。
- **输出长了，页面自己跟上**：每 4 秒取一次，而且**只换那一块**（不整页重画，
  免得把人正在看的东西刷掉）。没有新字时只更新时间戳那一行。
- 没在跑的活还是老样子（"它自己输出的内容"），不假装在动。

**又修了一处**（用户指出"重复显示这种正在写代码好像有点单调"）：worker 的日志
常常是"第 12 步：改代码""第 13 步：改代码"这样**只差一个计数**的行 —— 逐行看每行
都不同，说的却是同一件事。现在比的是**去掉计数之后的内容**，连着相同的折成一条
（×N），只给最近 8 步、新的在上面，原始记录收在"看原始记录"里。

真跑（真平台 8849 + 真日志文件）：一开始第 1–5 行，九秒后第 1–8 行 ——
**没刷新、没点任何东西**。状态跑完已还原。

新增 `office/scripts/verify-office-live.mjs`（列表有心跳点 / 详情是"正在做什么" /
输出长了页面自己跟上 / 页面不报错）。

## 边界：什么**不**补，和为什么

按 R10 §39 与 `docs/tasks/notes/OFFICE-UI-01.md`（"派单、拆解、裁决、合并一律
由管理员 Harness 与成员自己走 API 完成，界面不代点"），下面这些**不进群主面**：

| 端点 | 不补的理由 |
|---|---|
| `POST /api/v1/adapter/admin/refine` | 需求细化是管理员面的活（R10 §22：群主只说目标，管理员细化并分派） |
| `POST /api/v1/groups/{id}/dispatch` | 派单归管理员 harness；网关的注释也明写"不得恢复人工派单" |
| `POST /api/v1/review/claim`、`/review/submit` | 审查归管理员与成员 |
| `POST /api/v1/human/adjudicate` | **裁决**归管理员面（R10 §39）。补它等于把裁决搬回群主面 |
| `POST /api/v1/projects` 等管理链 | 建项目/建群/发方案是管理员的动作；办公室大厅的"新建项目"按设计只写本机 localStorage |

代价要说清楚：**`escalated` 在群主面只有"放行"一条出口**，没有"受理升级 → 让人
回答"那条链（`human.adjudicate`）。要补那条链，得先有管理员面，那是另一张卡。

`human/adjudicate` 本身仍然够得着：网关有路由，CLI 有 `human-adjudicate`。

## 怎么做到不出错

1. **状态门控是抄后端的，不是凭感觉**：前端的状态集合在 `office/src/human-actions.js`，
   冒烟脚本从 `backend/app/human/service.py` **解析**出后端守卫再逐个比对，
   后端一改，前端这边立刻红。
2. **预算是显式问的**：R10 §8 规定预算用完的活普通的 release 会被拒绝，
   所以"放行"按钮在需要时明确问一次"顺便再给一次机会"，而不是让人从 409 里猜。
3. **不改后端**：这五个端点早就在，零后端改动、零 schema 改动、零事件名改动。
4. **说法改了不能把断言改松**：平台助手里那两个按钮（批准、改派）改了措辞，
   `verify-platform-assistant.mjs` 的断言同步改成新措辞 —— 断的是"这一节只该有
   人的批准按钮"这件事，不是"按钮必须长这样"。

   后端守卫逐个相等、每个状态该有哪些按钮、预算豁免要显式问、
   网关把五个请求送到哪个后端端点并带对字段。
2. `office/scripts/verify-office-human-actions-ui.mjs` 绿（浏览器实测）：
   按钮真的渲染出来、点了真的打出 `/human/resume` 与 `/plan/reject`、
   页面不报错。该脚本自带静态服务器并拦截全部 `/api/formal/*`，不连在线平台。
   另外断言三条**走查才发现**的东西：回答的对话框里不出现预算勾选框、
   处置对话框高度按内容收着（< 400px）、预算用完的活放行前会问一次
   "再给一次机会"并带上 `budget_override`。
3. 界面上不出现平台内部名：`attempt` / `epoch` / `决策行` / `预算豁免` / `mention` /
   `stdout` 一律换成人话；窗口显示平台登记的名字而不是 id。
4. 「各个窗口都说了什么」独立窗口可用：按窗口分组（键是"这一次是谁做的"）、
   每一次尝试都摊开、显示原文、默认只显示做完了的、输出里的 HTML 被转义
   （CLI 说 `<b>x</b>` 时页面上是字面量）。
5. 既有冒烟全绿（`verify-office-task-view` / `brief-members` / `admin-chat` /
   `direct-chat` / `brief-live` / `layout` / `project-scope` / `platform-assistant` …）。
6. `office/` 构建通过（`npm run build`）。
7. `./scripts.sh check` 三道门禁全绿（docstate + discipline + ruff + pytest）。
8. `docs/traceability.md` 登记 `MVP-UI-012`（按钮）、`MVP-UI-013`（说法）、
   `MVP-UI-014`（独立窗口），状态如实写"部分有断言" —— 前端的静态检查
