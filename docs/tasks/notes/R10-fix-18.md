## 做什么

平台加一条**定向消息**通道：一条带 `direct` 签名的群消息，**只有发送方与收件人看得到**；
办公室给它一个独立的私聊窗口。

## 为什么

用户要"直接和管理员对话"。查下来平台**从来没有过**私聊：

- schema 只有 `task_messages` 与 `message_deliveries`；
- R10 正文与 backend 里没有 direct/private/dm 概念；
- 旧的"定向求助"是 `help-messaging-mock` 那个**模拟**组件。

而群消息整群可见（成员的 task 上下文里会出现它，§19 的"最近 N 条消息"），
所以"在群里 @ 管理员"不是私聊——除非读路径真的按收件人过滤。

## 修法

见 R10 §38.13。要点：

- 落在消息的 **refs** 里（`direct` 只是一个签名串），**不新增表、不新增列**；
- **可见性在读路径上判**：服务层按观看人过滤，路由层用令牌主体作观看人，
  识别不出身份时**看不到**（失败关闭）；
- 收件人沿用 mention 的投递记录（`message_deliveries`），不另建一套；
- **不新增事件名、状态、状态迁移边** → `schema_version` 不动；
- CLI 的 `say` 加 `--mention` / `--direct`。

前端：办公室新增独立的私聊页（`office/direct.html`），只列定向消息，发出去也带
`direct`；办公室右栏多一个"开私聊窗口"。

## 边界

办公室仍是观察面：私聊窗口只提供**人自己的动作**（说话），不代管理员决定任何事。
前端只是把平台已有的定向消息摆出来，不自造可见性规则。
