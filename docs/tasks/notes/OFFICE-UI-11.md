## 做什么

**开工向导的措辞也按书面口径统一。**

真跑一遍（真平台 + 真按钮）之后发现：办公室那一屏已经说人话了，但点「配置目标」进入
开工向导之后，机器词全回来了。向导是**第一次用的人走的第一条路**，它比办公室更该
先说人话。

具体六处：

1. 成员栏：「成员实例（仅显示已注册窗口；同 Harness 的不同 instance_id 可同时加入）
   · 容量(宿主) 7 · 已选 7」→「成员窗口（仅显示已登记窗口；同一程序的不同窗口可同时
   加入）· 可用 7 个 · 已选 7 个」
2. 管理员栏：「管理员实例（只能选一个；其他实例在下面选为成员）」→「管理员窗口（**必选**，
   只能选一个；其余窗口在下方选为成员）」
3. 没选管理员就点「查看配置摘要」：「未选择唯一管理员」→「请先选择管理员窗口」
4. 摘要标题：「配置摘要（请宿主确认）」→「配置摘要」
5. 摘要行：「普通打工人」→「参与成员」；管理员那一行去掉实例 id 与「（harness）」
6. 摘要说明：「管理员 Agent 会细化并分派，成员 worker 再自己领取执行」→「管理员窗口会
   细化并分派，成员窗口再自行领取执行」

外加两处：

6. 确认开工之后那一屏（组件的彩排）标明是**界面演示**，不是真实回复；
7. 右栏「可执行成员 · 0 个」那句不再说「请去指定管理员与成员」—— 人在新建项目时**已经指定过了**（成员要等开工配置确认、目标提交之后才在平台上生效），改说「已选 N 个成员窗口，在「开工配置」确认后生效。」

## 为什么

仓库主人要求「实际跑一遍流程，用前端的按钮去点，重头开始新建项目」。那一趟走下来：

- 大厅 →「新建项目」→ 创建 → 空办公室 → 点「配置目标」→ 向导 → 选管理员 → 写目标 →
  看摘要 → 确认开工 → **目标真的进了项目群**（群里 182 → 183 条，新消息是
  「项目目标（端到端验证-1024）：把这周的办公室改动写成一份一页说明，交给管理员细化
  并派单。」）—— 流程本身是通的；
- 但向导那几屏的措辞全是机器词，而且**管理员是必选的这件事没说**，不选就只得到一句
  术语错误。第一次用的人到这里最容易卡住。

## 怎么做到不出错

1. **只改显示，不改行为**：组件的校验规则、提交内容、事件一律不动；替换只发生在渲染
   出来的文字上（仓库既定做法：宿主用 MutationObserver 改文字，锁定组件本身不动）。
2. **顺序有意义**：具体句式（「未选择唯一管理员」）排在通用词（「打工人」）之前，否则
   会被拆成半截话。
3. **摘要里不带实例 id**：界面上给人看的是登记名。
4. **钉住**：新增冒烟断言每一屏的措辞。

## 完成标准

1. 向导各屏不含 Harness / instance_id / 容量(宿主) / 实例 / 打工人 / 宿主 / 唯一管理员。
2. 管理员栏说清是必选；没选时的提示是「请先选择管理员窗口」。
3. 摘要标题是「配置摘要」；行名是「参与成员」；说明句说的是「管理员窗口 / 成员窗口」。
4. 确认开工那一屏标明是界面演示。
5. 新增冒烟 `office/scripts/verify-office-opening-copy.mjs` 通过；办公室全部冒烟无回归；
   `office/` 构建通过；`./scripts.sh check` 全绿。
6. `docs/traceability.md` 登记 `MVP-UI-026`。
