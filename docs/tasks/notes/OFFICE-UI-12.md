## 做什么

**办公室左边改成会话列表**（像电脑版微信那样）：

左栏一列会话，每行是「谁 + 现在怎么样」：

| 会话 | 状态摘要来自 |
|---|---|
| 项目任务 | 多少件事、几件在等人接 |
| 项目群聊 | 最后一条消息（人话） |
| 平台助手 | availability |
| 管理员 · 某某 | availability + 它手上的活 |
| 成员 · 某某 | 同上 |

点谁看谁 —— **中间那一栏**变成那个对象的内容：

- **窗口** → 状态页：在线/离线、用哪个模型、本项目里的活与进度、最近一次尝试、
  它的轨迹（平台事件）、它现在正在做什么（正在跑那条活的实时日志）；
- **群聊** → 群消息直接铺开（不是空框），还能就地发言；
- **平台助手** → 它的状态 + 一个「打开平台助手面板」的入口；
- **项目任务** → 任务表（按人归堆 + 筛选 + 排序 + 分页），点一条活看详情，详情带
  「← 返回任务表」。

## 为什么

仓库主人：「左边改成类似电脑版微信那样，显示群聊和每个对应的管理员、成员、平台助手，
点进去以后可以看到对应的 harness 的状态，比如现在正在做什么，进度这种，都是目前可以复用的」。

现在的办公室看不到"**每个窗口现在在干什么**"：一个窗口在做哪条活、做到哪一步、上一次干了
什么、能不能接活 —— 这些事实平台早就给了（availability / tasks / events / output），
只是没摆到界面上。而左栏现在只有任务表，人要在"谁在干什么"和"活怎么样"之间来回找。

## 怎么做到不出错

1. **数据一律复用现成的**：availability（在线/离线、模型、能不能接活、上一次在干什么）、
   tasks（手上的活、状态、尝试次数）、events（轨迹）、output（实时日志，与任务详情同一端点）。
   **不新增后端接口，不猜。**
2. **说清范围**：availability 是整群的、任务是本项目的 —— 事实表写「**本项目里**的活」。
3. **还在跑的就不是「上一轮」**：状态摘要区分「正在做」与「上一轮：<状态>」。
4. **主从切换有回去的路**：详情能「← 返回任务表」；窗口状态页点某条活能跳到那条活。
5. **加载态说清楚**：窗口名单第二批才到（要探 CLI 配置，慢），这段时间左栏说「正在读…」。
6. **群聊在中间时消息默认铺开**（底部压缩条子里才是收起的），否则人对着一个空框。

## 完成标准

1. 左栏是会话列表：项目任务 / 项目群聊 / 平台助手 / 管理员 / 每个成员窗口，每行有名字与状态。
2. 点一个窗口 → 中间是它的状态页（在线、模型、本项目里的活、最近一次尝试、轨迹、正在做什么）。
3. 点群聊 → 中间是群消息（铺开、可发言）。
4. 点项目任务 → 中间是任务表；点一条活 → 详情 +「← 返回任务表」；返回后又是任务表。
5. 新增冒烟 `office/scripts/verify-office-conversations.mjs` 通过；办公室全部冒烟无回归；
