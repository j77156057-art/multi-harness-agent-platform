## 做什么

办公室的任务列表**按窗口归堆**：每个窗口一块，块头写清它是谁、手上几条、忙还是
闲；块里是它接的活（按当前状态排）。筛选项从"按状态筛"扩到"按人看"。

## 为什么按人

- 现在按状态排 → 人看到"这件事到哪一步"，答不上"**谁**在忙、**谁**闲着"。
- 办公室的日常问题是"今天该找谁"、"这个窗口是不是已经压了一堆活" —— 都要**按人**
  看才答得上来。
- 输出页已经是按窗口摊开的（"各个窗口都说了什么"），办公室的任务列表却不是 ——
  同一个产品里两种看法。

## 怎么做到不出错

1. **分组依据是平台的事实**：谁手上有什么活、活到哪一步，都从平台来的状态算，
   不猜、不用本地记的次数。
2. **忙闲要有依据**：块头写"忙/闲"必须有平台侧事实支撑（手上有在办的活 vs 没有），
   拿不到就不写这句话。
3. **分组是显示层的事**：后端接口、状态机、事件名一概不动。
4. **状态筛选还在**：按人看和按状态看要能同时用，不是二选一。

## 实现要点

### 归堆的依据（都是平台的事实，不猜）

- **现在谁在做**就归谁（`task.owner`）。
- 做完了、没做成的归**最后接过的那个人** —— 一条活做完没人接手，它还是那个人的活。
  这里要用**领取事件**（`claim`/`start`/`claim_for_revision`/`take_over`），因为平台合入
  之后会把 owner 清空（真数据实测：合入后的活 owner 是空的）。
- 没人碰过的归「还没人接」。

**忙闲是从"手上"推出来的**：手上有在做的活（`claimed`/`in_progress`/`verifying`）就是
"在忙"，没有就是"闲着"，没人接的那一块是"等人接"。不是另猜的一个字段。

### 两处必须小心

1. **按 id 归堆，不按名字**。两个人可能同名；而且 `whoHolds` 给的是**名字**，名字不能
   当钥匙 —— 所以另拆一个 `holderIds()` 给 id，`whoHolds()` 负责换成名字。
2. **事件必须和任务表一起到**。办公室的刷新是分两批的（先画任务表，再补右栏与群聊，
   因为额度池要问 provider 的余额，慢）。但按人归堆要知道谁接过活 —— 分两批到的
   话，第一屏会先摆成"一堆没人接"，等事件到了再重排，**一闪**。所以事件挪到第一批。

### 界面

- 块头：登记名 + 忙闲徽章（在忙 / 闲着 / 等人接）+ 数（手上 N 条 · 等着 N 条 ·
  做完了 N 条 · 没做成 N 条，只有非零的才写）。
- 归堆的行里**不重复写"谁在做"**（块头已经写了）；「还没人接」那一块例外 ——
  那里没有名字，行里得说清"现在没人做"。
- 看法切换「按人 / 按时间」放在工具条上；按人是默认。
- 块的顺序是一句话：**谁在干活 → 活还缺人 → 谁有空**。
