## 做什么

**第一次用的人有路。**

具体是四件事：

1. **空项目的空状态说人话，并给一个能点的下一步**：
   顶部那句话说清「现在是什么 + 点哪里」；左栏只留「还没有活」；中间那栏（空项目里
   最大的一块空白）说清这一栏将来会出现什么，并给一个「去写第一件事」的按钮 ——
   点它真的打开开工向导。没有活可筛时，筛选条/排序/每页/分页**收起来**。
2. **把界面上给机器看的词换成人话**：项目配置表单里的「成员 Harness」「Harness 成员 ·
   online」「正式项目范围：112 / office-formal-2 · 7 个可领活的成员窗口」。
3. **大厅那三步引导跟界面上真的按钮对得上**。
4. **私聊发出去后说清楚「在等」**：管理员回话要过一次模型（慢），不说的话主人以为消息丢了。

## 为什么

这几条不是推演出来的，是**自己走了一遍第一次使用的流程**（新建项目 → 落到空项目的
办公室）看到的：

- 中间那栏写「选一条任务看它的规格、事件轨迹和 CLI 原话」—— **可一条任务都没有**，
  等于让第一次用的人去找一个不存在的东西；
- 空项目里左栏摆着八个没有对象的开关和「第 0–0 条，共 0 条」，比界面真正要说的那件事
  还显眼；
- 同一件事在顶栏与左栏各说一遍；
- 项目配置表单里摆着 Harness、平台凭据、项目号/群号 —— 第一次用的人看到只会以为界面
  漏了东西；
- 大厅三步写「填写项目名称与成员 / 直接进入开工配置 / 开工向导里挑管理员和成员」，
  而界面上真的按钮只有「新建项目 / 连接工作窗口」，对不上；
- 私聊发出后只有自己那条消息挂着，没有一句「在等」。

## 怎么做到不出错

1. **每一处只说一件事**（顶部说下一步、左栏说事实、中间栏说将来会出现什么），不再三处
   各说一遍。
2. **不改既有断言的意图**：`verify-office-project-scope.mjs` 断言空状态含「还没有任务」，
   新文案保留这句话，只是不再重复后面那一整段。
3. **空项目才生效**：筛选条与分页条只在**一条任务都没有**时收起，有活可筛时原样不动。
4. **按钮要真的能点**：不是画一个假的「去写第一件事」，而是打开真的开工向导，并用冒烟
   钉住「点了之后向导确实打开了」。
5. **私聊的提示按事实来**：只有「最后一条确实是我发的、还没人回」才显示「在等」，
   管理员一回复就不再显示。
6. **这一轮只改前端**：平台行为一行不动（`backend/**` 不碰）。
