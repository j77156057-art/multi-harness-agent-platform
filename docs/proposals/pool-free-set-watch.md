# 提案：免费档目录变更哨（pool-free-set-watch）

状态：**已实施**（2026-10-23，仓库主人指示"继续完成其他的"后开工）；
规范条目（新检查 ID/事件名）不动真相源，获批后再落。裁决三问的现行
默认见任务卡"实施采用的现行默认"，可推翻重配。

## 问题

免费档天然易变：免费额度会失效、免费模型会被下架、新的免费模型会出现
（2026-10-21~23 两天内目录已见增删）。池子目录本身是动态的（discovery +
TTL + `tier` 标签），但**目录变了没人喊**——消费方（如平台助手）要么用到
死链，要么错过新免费档，人对目录的印象也要靠撞上才知道过期。

## 分工（顺着"if/else 归代码"的尺子）

| 层 | 谁 | 做法 |
|---|---|---|
| 目录真相 | 池子（现成） | 不改；models() 继续 TTL 刷新 |
| 变更检测 | 平台代码（新采样器） | 快照 free 集合 id 列表（按内容 hash 做去重键），diff 上一张快照 |
| 通知 | alerts（现成） | `service.enqueue(kind="pool.free_set_changed", payload, source_key=hash)`——入队/投递面已有，**不新增表不新增事件** |
| 处置 | 人＋助手 | 人复查目录/替换凭据；助手被问起时用现行目录如实作答 |

探测原则呼应助手通道已有的选择：**被动为主**——目录 diff 是零成本采样；
不主动轮询烧 CLI 槽验证活性（一次探测就是一次真实调用），活性由消费端
冷却机制喂探针。配置可选加"目录增删超过 N 个模型必须人审"的阈值。
