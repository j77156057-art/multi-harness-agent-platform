目标：**把「它的轨迹」讲成人话** —— 让人一眼看懂这个窗口到底做过什么。

为什么：仓库主人看截图后说：「截图里显示的轨迹没看明白是什么意思」。

现在的样子（真跑看过的）：

```
它的轨迹
  10/22 15:10   批改了        Codex · 管理员
  10/22 14:37   方案批准了     Codex · 管理员
  10/22 14:37   取消了        Codex · 管理员
```

三处读不懂：

1. **「它的轨迹」本身没说这是什么** —— 人不知道这是一串动作记录。
2. **没说动的是哪条活** —— 「批改了」批改了什么？只有事件自己的聚合号，人对不上号。
3. **展开是机器噪声** —— 真数据里 `approve` 事件的 payload 是
   `findings_hash` / `reviewed_commit` / `review_id`（哈希与 commit），摆出来像玄学。

范围：

- `office/src/flat-office.js`：
  - 轨迹块加一句说明（这是什么、怎么看）；
  - 每一行补上**这条活的名字**（用办公室已有的任务表换名字，不显示编号）；
  - payload 只留**给人看的**字段（哈希、编号、commit 这类机器字段不摆），一个都不剩
    时说「这个事件没有要人看的细节」。
- `office/src/flat-office.css`：新增的行样式。
- 办公室冒烟加断言。

**不碰** 后端、不碰 `docs/spec/**`、不动其他 Harness 的工作区与分支（这是纯显示的事）。

## 怎么做到不出错

1. **动作和对象都写出来**：「批改了「收一条真实任务」」—— 动作 + 对象，才是一句话。
2. **机器字段不摆**：哈希、commit、内部编号对人没有意义；藏进 title（鼠标悬停可见）。
3. **不猜**：活的名字取自办公室已经有的任务表；取不到就退回编号，不编。
