目标：**办公室左边改成会话列表**（像电脑版微信）—— 项目群聊、平台助手、每个管理员与成员窗口
列成一栏，点进去看那个对象现在在做什么、进度如何。

为什么：仓库主人要「左边改成类似电脑版微信那样，显示群聊和每个对应的管理员、成员、平台助手，
点进去以后可以看到对应的 harness 的状态，比如现在正在做什么、进度这种，都是目前可以复用的」。

现在的办公室左栏是**任务表**（按人归堆），右栏是几张卡片，**看不到"每个窗口现在在干什么"**：
一个窗口在做哪条活、做到哪一步、上一次干了什么、能不能接活 —— 这些事实平台早就给了
（availability / tasks / events / output），只是没摆到界面上。

范围：

- `office/src/flat-office.js`：左栏换成会话列表；中间那一栏按选中的会话给内容；
  任务表搬进中间那一栏（「项目任务」是第一个会话），任务详情带「← 返回任务表」；
- `office/src/flat-office.css`：会话列表的样式；群聊在中间时消息默认铺开；
- `office/scripts/verify-office-conversations.mjs`：新增冒烟（自带静态服务器 + 拦全部 API）。

不碰 `backend/**`（**全部复用现成数据**：availability 的在线/模型/能不能接活/上一轮、
tasks 的手上的活与进度、events 的轨迹、output 的实时日志）、`docs/spec/**`、
`office/contributions/**`、其他 Harness 的工作区与分支。

## 怎么做到不出错

1. **数据一律复用现成的**：availability（在线/离线、用哪个模型、能不能接活、上一次在干什么）、
   tasks（手上的活、状态、尝试次数）、events（它的轨迹）、output（它现在正在做什么，
   与任务详情同一个端点）。不新增后端接口，不猜。
2. **说清范围**：availability 是整群的，任务是本项目的 —— 所以事实表里写「**本项目里**的活」，
   不让人以为"它一件活都没有"。
3. **还在跑的就不是「上一轮」**：状态摘要区分「正在做」与「上一轮：<状态>」。
4. **没有对象的开关不出现**：左栏是会话列表，没有活可筛时那排筛选条不再占地方。
5. **主从切换有回去的路**：从任务详情能「← 返回任务表」；从窗口状态页点某条活能跳到那条活。
6. **加载态说清楚**：窗口名单是第二批才到的（要探每个 CLI 的配置，慢），这段时间左栏说
   「正在读…」，不空着像"这个项目里没有窗口"。
