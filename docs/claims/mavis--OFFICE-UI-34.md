目标：**助手面板改成能正常对话的样子** —— 多轮连着聊、它记得前面说过什么、
你能看见它自己在一轮里做了什么。

## 现状（上一张卡之后）

面板已经是「项目速览 + 问一句 + 它的回答」，但：

- **不是对话**：我的提问与助手的回答是两块分开的东西，没有一问一答的先后；
- **没有记忆**：助手每轮只看得到当前这一条提问（`loop.run(question, context)` 的
  context 只有 `[c1]` 一行），上一轮我问了什么、它答了什么，它全不知道；
- **看不见它在做什么**：它一轮里调了哪个工具、看到什么，只在服务器本地的 trace
  文件里，界面上一个字都没有 —— 于是「能自己 react」这件事用户只信一半。

## 范围

- `office/src/flat-office.js`、`office/src/flat-office.css`：助手面板改成对话流
  （我的提问与它的回答按时间交替、输入区固定在底部、连续追问）。
- `backend/app/assistant/memory.py`（**新增**）：从平台消息流里取同一条私聊线程
  此前的人机问答 —— 助手的记忆从这里来。
- `backend/app/assistant/worker.py`：**最小接入**（把历史交给 loop 的 context）。
- `backend/app/api/routes.py`：新增只读端点 `GET /assistant/runs`（最近几轮助手
  的步骤摘要：调了哪个工具、看到什么、最后答了什么）—— 放 read 区块，避开 codex
  在途的 hunk。

## 怎么做到不出错

1. **记忆走已有的引用机制**：`loop.run(question, context)` 的 context 就是
   `[c1]…[cN]` 引用行，历史按同样格式追加即可 —— **不改 loop.py**，机械门
   （引用必须解析得到）照旧生效。
2. **历史是数据不是命令**：历史内容与本轮提问一样进 `DATA (untrusted)` 围栏。
3. **不碰 codex 的在途范围**：`assistant/**` 是 `assistant-react-loop` 卡的
   「允许修改」范围，这里只**新增**一个文件 + `worker.py` 一处接入；引擎
   （loop.py）、工具表、prompt 都不动。
4. **助手仍然只读**：记忆与轨迹都是读面，助手不改现状。

## 完成标准

1. 助手面板是**对话流**：一问一答按时间交替，输入区固定在底部。
2. 助手**记得上一轮**：连着问两轮，第二轮的回答里能引用第一轮的内容。
3. 用户**看得见它在一轮里做了什么**：面板里列出它调的工具与看到的结果。
4. 后端全量 pytest 通过；门禁全绿；办公室冒烟全绿。
5. `docs/traceability.md` 登记 `MVP-UI-049`。
