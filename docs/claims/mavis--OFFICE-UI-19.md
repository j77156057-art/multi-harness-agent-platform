目标：把窗口页的「它用哪个模型」收口成三件事：

1. **收费额度也要能选，但要点头** —— 按量计费的模型（每调用一次都花钱）必须人明确
   同意，平台才肯花；「你自己的 key」仍按原来的规矩要人点头。
2. **清单折叠起来** —— 二十几个模型铺开把整页挤走，收进一个可展开的清单里。
3. **加一个探针** —— 点刷新时**重新探一遍**池子：这样「某个免费额度改成收费了」和
   「新加了免费额度」都能被发现，而不是让人以为免费额度一直是免费的。

为什么：仓库主人：「那么收费额度呢，另外折叠起来，别弄太长，另外加个探针，点击刷新
的时候可以重探模型，防止之前的免费模型重新收费，或者加入新的免费模型却不知道」。

现在的事实（查过代码才敢这么说）：

- **池子的清单是缓存的**：`app/pool/service.py` 的发现结果默认缓存 30 秒
  （`DISCOVERY_TTL_SECONDS`），而且**没有人会去清它**（`invalidate_discovery()` 只在
  用户增删自己的 key 时被调）。所以「新的免费额度上线了」「某个额度改成收费了」这两
  件事，办公室可能一直不知道。
- **「免费」只是一个声明**：`app/pool/sources.py` 里每个额度槽自己声明
  `tier`（`free` / `reserve` / `metered`）。声明归声明，**没有人核对它现在还是不是
  免费的** —— 改配置就能把一个 `free` 改成 `metered`。
- **平台照办时也不看档位**：`plan_attempt` 只认「人选了哪个模型」，不认「人点头时
  那一档是什么」。所以免费额度变成收费额度之后，平台会照旧去花它。

范围：

- `backend/migrations/018_harness_model_tier.sql`：`harnesses` 加 `model_tier`
  （**记下人点头时那一档**；新增 schema → 必须有迁移）。
- `backend/app/adapter/model_choice.py`：选择里带上 `model_tier`。
- `backend/app/api/routes.py`：选**按量计费**的模型要人明确点头（`paid_consent`），
  没有就拒并说清为什么。
- `backend/app/pool/routing.py`：人点头时那一档是免费、而现在这一档变成收费了 →
  **不再花它**，回落到自带并写明「要你重新点头」。
- `backend/app/pool/routes.py` + `office/server/formal-dispatch-gateway.mjs`：
  `POST /pool/probe`（清缓存 + 重探 + 回一份新的清单）。

  收费模型的确认、探针按钮与变化提示（新增的免费额度 / 变成收费的额度）。
- `office/src/main.js`：顶栏加「刷新」—— 点了就重读数据**并**重探池子。
- `backend/tests/test_harness_model_selection.py`：加断言。

  提交**）。

**不碰** R10 §10 状态机、§37.7 事件 allowlist（不新增事件名/状态/迁移边 → 事件
`schema_version` 不动）、其他 Harness 的工作区与分支。

## 怎么做到不出错

1. **收费一定要点头**：选按量计费的模型时，没点头平台就拒（409），界面弹确认；
   点头这件事本身记在选择里（`model_tier`），不是界面的一次性动作。
2. **免费变收费就不再花**：平台照办前先核一次「人点头时那一档」与「现在这一档」；
   对不上（免费 → 收费）就回落自带，把原因写进答复 —— 不静默多花钱。
3. **新的免费额度要看得见**：探针返回的清单与上次那份比，多的、变档的都摆出来；
   上次那份记在浏览器里（localStorage），刷新页面也在。
4. **探针不常跑**：只有人点了刷新/「重新探一遍」才重探（每探一次要问二十几个上游），
   平时 15 秒的自动刷新仍读缓存。
