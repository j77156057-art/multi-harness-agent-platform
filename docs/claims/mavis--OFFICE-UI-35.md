目标：**助手的回答不再半截**。

## 现象（真跑看到的）

在办公室问「本项目有几条任务？其中多少条还没人领？」，助手的回答是完整的（有结论、有
依据、有建议），但中间有一句：

> 未领取的 ready 共 21 条[c3]。但完整 ID 清单未记上：[c3] 只列到 FD-1f5165d93d235561、
> FD-4aa87412ced0dc60、FD-5732b1a92629b896、FD-6361e6fd867b9315，随后在 **FD-76…**
> 处被截断[c3]。

界面上看到的就是「回答后面都有省略号」，分不清是**没答完**还是**清单被切了**。

## 根因（查到了）

不是界面的问题，也不是模型偷懒：**平台消息里的原文是完整的**（583 字符，有结尾）。被切
的是**它看到的那份工具观察** —— `group.tasks` 把本群 74 条任务的**全字段**整份塞进一次
观察（几十 KB），模型只看到前面一半，于是它如实说「在 FD-76… 处被截断」。

也就是说：**喂给模型的数据被切了半截**，模型没有编（它明说「其余条目的完整 ID 我未
记上，也不补编」）—— 但体验上就是「回答没答完」。

## 修法

`group.tasks` 不再把全表整份塞进观察，改成**结构化摘要 + 可分页**：

- 计数：总数、按状态分布；
- 清单：没被领的、已有人领的，各带**少量字段**（id / 标题 / 状态 / 持有者）；
- 明确说清**省略了多少条**、**怎么翻页**（`limit` / `offset`）。

这样模型一次看到的是**完整摘要**而不是半截清单；要看全量时它可以自己翻页。

## 怎么做到不出错

1. **不碰引擎、不碰提示词、不碰工具名单**：`loop.py`、`prompts.py`、工具的注册表一律
   不动；只改 `group_tasks` 往**观察里放什么**。
2. **codex 的在途**：`assistant/**` 是 `assistant-react-loop` 卡的「允许修改」范围，但那
   张卡的实质工作（引擎 / 工具 / 私聊轮询）已落在 main 上、其工作区干净。这一张只动
   **一个函数的返回形状**，不碰他的引擎与提示词；他的测试（`test_assistant_loop.py`）
   只断言工具名，不断言返回形状 → 不会被他改坏。
3. **摘要里必须说清省略了多少**：不能让「没列全」变成另一种看不见的截断。
4. 助手仍然只读。
