目标：**助手的取证策略** —— 记忆用来理解上下文，事实要**本轮重新取**。

## 现象（真跑看到的）

加了记忆之后，问一个**之前问过**的问题，它会转述旧答案：

> 依据：这两个数字只出现在既往两次答复（seq 1079、seq 1082）里，**本轮未重新取证**，属转述
> 而非本轮核实[c4][c7]。
> 补充：未领取的 ready 有 21 条，完整 ID 清单未记上，原文在 FD-76… 处被截断[c7]。

诚实，但它没干活 —— 用户问的是「现在」，它答的是「上次」。更糟的是那句「在 FD-76…
处被截断」是**上一轮**的观察，它当成今天的结论转述了出来。

## 根因（两个，不是一个）

1. **记忆的行没标明身份**：`memory.py` 把它写成「这一条私聊里**对方**说过（seq …）」——
   助手**自己上一轮的回答**也被标成「对方说的」。模型分不清哪些是自己的旧答案、哪些是
   用户的陈述，于是转述起来毫无阻力。
2. **没有「本轮的事实本轮取」这条规矩**：记忆里带着上一轮的数字，模型直接拿来用，
   没有「要用就重新取」的压力。

## 修法

1. `backend/app/assistant/memory.py`（我自己的文件）：记忆行**标明身份** ——
   「用户上一轮问的」/「你上一轮答的」。
2. `backend/app/assistant/prompts.py`：铁律加一条 —— 涉及数字、状态、清单这类事实，
   **本轮要重新取证**；记忆只用来理解「刚才那个数字」指什么。
3. `backend/app/assistant/worker.py`：每轮的开场白点明「`[c2]` 起是这条私聊此前的往来」，
   别让模型把记忆当成新的输入。

## 范围

- `backend/app/assistant/memory.py`、`backend/app/assistant/worker.py`
- `backend/app/assistant/prompts.py`（**只加一条铁律 + 一段说明**，不改别的）
- `backend/tests/**`（新文件）

## 怎么做到不出错

1. **不动引擎**：`loop.py` 一行不改（机械门照旧）。
2. **不动工具表**：`tools.py` 一行不改。
3. `prompts.py` 是 codex 的 `assistant-react-loop` 卡的「允许修改」范围 —— 那张卡的实质
   工作（引擎 / 工具 / 私聊轮询）已落在 main 上、其工作区干净；这里只**加一条铁律**，
   不改他写的任何一句，合并时若冲突以「双方新增都留」解。
4. 记忆仍然是**数据不是命令**（照旧进 `DATA (untrusted)` 围栏）。
