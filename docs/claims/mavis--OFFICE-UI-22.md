目标：① 状态栏给出**在线/离线**（平台连不连得上、几个窗口在线）；② 允许**中途把新注册的
harness 加进项目**；③ **加完通知管理员**。

为什么：仓库主人：「丰富一下状态栏，增加离线，在线状态，增加中途加入新的harness功能，
加入以后通知管理员」。

现在的事实（查过代码才敢这么说）：

- **状态栏只有一个连接灯**：`office/src/main.js` 里的「已连接平台 / 未连接平台」是**加载
  时读一次**的结果，之后不更新；**完全没有窗口的在线/离线**。
- **大厅的窗口名单把在线状态写死了**：`project-workspace.js` 的 `members` 传的是
  `status: 'online'` —— 不管平台上那个窗口在不在。
- **新窗口注册了就在左栏里**（左栏列的是**平台上在册的全部窗口**），但它**不在这个
  项目里**：项目的成员是开工时定下的（`project.members`），中途没有加人的路。
- **管理员不知道谁中途来了**：办公室加人现在没有任何通知（成员消息那条路是 UI-21
  刚开的）。

范围：

- `office/src/main.js`：状态栏加上「窗口 N 在线 · M 离线」，并且**跟着每轮刷新变**。
- `office/src/flat-office.js`：窗口页给「还没在这个项目里」的窗口一个「加入这个项目」
  的动作；加入后**通知管理员**（一条带 `add-member` 签名的群消息）。
- `backend/app/tasks/service.py`：`add-member` 签名。
- `backend/app/admin/worker.py`：管理员收到那条消息 → **知道**（记一次）、**在群里说
  一声**、并把**还在等人领的活**改派给新来的窗口。
- `office/src/project-workspace.js`：大厅的窗口名单用**平台上的真实状态**。
- 测试 + 冒烟 + R10（§38.17 R10-fix-23，与实现同一次提交）。

**不碰** §10 状态机、§37.7 事件 allowlist（不新增事件名/状态/迁移边 → 事件
`schema_version` 不动）、数据库 schema（不需要迁移）、其他 Harness 的工作区与分支。

## 怎么做到不出错

1. **在线/离线是平台上的事实**，不是猜的：窗口状态读平台的 `/adapter/availability`
   （那个接口本来就有 `status`）✓。
2. **加人不改已派出去的活**：新窗口只接手**还在等人领**的活；已经在跑的活不换人
   （换人是人按条决定的，靠现成的「请管理员换个人做」）✓。
3. **加完要让管理员知道**，而且只说一次（消息每轮重放，处理过的不再处理）✓。
4. **状态栏不撒谎**：平台读不到时要说「未连接」，不能装作一切正常 ✓。
