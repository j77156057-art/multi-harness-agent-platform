目标：**开工向导的措辞也按书面口径统一** —— 第一次用的人走的第一条路上，不该出现
实例 / 打工人 / Harness / instance_id / 宿主 / 唯一管理员这类机器词。

为什么：仓库主人要求「实际跑一遍流程，用前端的按钮点，重头新建项目」。真跑之后
（8849 真平台 + 4174 预览，Playwright 一步步点）发现：办公室那一屏已经说人话了，
但**点「配置目标」进入开工向导之后，机器词全回来了**：

- 成员栏：「成员实例（仅显示已注册窗口；同 Harness 的不同 instance_id 可同时加入）
  · 容量(宿主) 7 · 已选 7」
- 管理员栏：「管理员实例（只能选一个；其他实例在下面选为成员）」—— 而且**没说是必选**，
  不选就点「查看配置摘要」，只得到一句「未选择唯一管理员」
- 摘要标题：「配置摘要（请宿主确认）」
- 摘要行：「普通打工人」、管理员那一行带着实例 id 与「（harness）」
- 摘要说明：「确认后只提交一条项目目标；管理员 Agent 会细化并分派，成员 worker 再
  自己领取执行。」
- 确认开工之后那一屏：「已创建开工聊聊」「重播演出」—— 那是组件的彩排，界面上却像
  是真的回复

范围：

- `office/src/opening-host.js`：沿用仓库既定做法（宿主用 MutationObserver 改**渲染
  出来的文字**，锁定组件本身不动），补一条通用的术语替换表，并把已有那两条措辞改成
  书面口径；
- `office/scripts/verify-office-opening-copy.mjs`：新增冒烟（自带静态服务器 + 拦全部
  API，不连平台也能跑）。

不碰 `office/contributions/office-opening-phone/**`（锁定组件）、`backend/**`、
`docs/spec/**`、其他 Harness 的工作区与分支。

## 怎么做到不出错

1. **只改显示，不改行为**：组件的校验规则、提交内容、事件一律不动；替换只发生在渲染
   出来的文字上。
2. **顺序有意义**：具体句式（「未选择唯一管理员」）排在通用词（「打工人」）之前，否则
   会被拆成半截话。
3. **摘要里不带实例 id**：界面上给人看的是登记名，id 是给机器看的。
4. **确认开工那一屏说清是演示**：正式平台下那几句彩排不是真实回复，不能让人以为成员
   已经回话了。
5. **钉住**：新增冒烟断言栏目标题不含 Harness / instance_id / 容量(宿主) / 实例，
   管理员栏含「必选」，提示是「请先选择管理员窗口」，摘要不含「请宿主确认」/
   「普通打工人」/「（harness）」/ 实例 id。
