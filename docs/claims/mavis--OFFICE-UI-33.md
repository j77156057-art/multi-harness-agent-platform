目标：**平台助手默认内置在工作区域** —— 不用在新建项目时另外选，随手能问。

## 现状

- 办公室左栏里那一行「平台助手」指向的是 `office-admin`（**管理员窗口**），它能
  播报、登记积压、协调事项，但不是那个能读日志、调记录、回答问题的助手。
- 真正能干这些的是平台后端的助手主体 `office-assistant`：有模型、有只读工具
  （`task.get` / `task.diagnose` / `task.review_pack` / `task.forensics` / `group.tasks`），
  靠**定向私聊**接提问（OFFICE-UI-31 刚给它补上日志取证）。
- 它的入口现在不在工作区域里，用户得知道它的 id、知道怎么发定向消息才用得上。

## 范围

- `office/src/flat-office.js`（工作区）：左栏与主视图
- `office/src/project-workspace.js`（新建项目：助手不是勾选项，不用改）
- `office/src/*.css`、`office/scripts/**`

## 怎么做到不出错

1. **默认内置**：入口**始终**在工作区域里，不依赖平台是否注册了某个窗口，
   也不需要在新建项目时勾选。
2. **名字归位**：`office-admin` 是管理员窗口，左栏别再把它标成「平台助手」；
   「平台助手」这个名字留给能问答的那个主体。
3. **速览是平台事实**：任务是否下发、成员是否正常领取、目前进度 —— 前端从
   `/api/formal/tasks` 直接算，不猜。模型不稳时用户照样拿得到速览。
4. **助手没在跑就说没在跑**：不装作有回答；助手只读、只答，不改现状。

## 完成标准

1. 新建项目不需要选助手；工作区域里始终有助手入口。
2. 助手面板给出项目速览，并能接收提问、显示助手的回答。
3. 真跑验证：工作区里能问出结果；办公室冒烟全绿。
4. `docs/traceability.md` 登记 `MVP-UI-048`。
