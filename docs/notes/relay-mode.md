# 转接模式（relay mode）：平台只负责把话送到

状态：M1 已实现（文件信箱 + relay worker）。作者：助理 agent。日期：2026-11-01。

## 0. 传输为什么是**文件**（而不是屏幕、也不是让每个 CLI 调接口）

2026-11-01 做过一组对照：同一个 CLI，同样的问题，两条路各拿到什么。

| | 终端（PTY） | 无头模式 |
|---|---|---|
| 平台拿到的东西 | 120 秒 2911 字节、**173 个控制序列**；用真 VT 模拟器（`@xterm/headless`）重建后**一行可用的都没有** | 结构化输出（JSON 行/字段） |
| 失败时 | 静默：发的人以为送到了，收的人永远没收到 | 有状态码与原因 |

而"写文件"是每个 coding CLI 都会做的一件事，写出来是**干净字节**、写完才被读到（原子），
不需要 VT 重建、不需要网络、不需要令牌 —— 也不需要每个 CLI 都有调平台接口的能力。
所以：**传输用文件，读取用文件，人看的是平台消息**。

## 1. 它是什么

一个**并存的运行模式**：平台不拆任务、不管工作树、不做校验与合并，只把 harness 说的话
按收件人送到该看到的人那里。分工、改哪个分支、谁审谁——是 harness 自己的事。

现有调度链路（方案 → 派单 → 领取 → 校验 → 审批 → 合并闸门）**一条都不改**。模式开关
关闭时，消息完全按今天的样子走。

## 2. 为什么不需要终端

内置终端是**给人用的** PTY：平台在那边只能看到一块屏幕字节流，读不出"这段是给谁的"
（§0 的实测）。所以转接落在**文件**上，终端仍只给人用。

## 3. 信箱目录（全部在 `<仓库>/relay/`，运行时产物，已进 .gitignore）

```
relay/
  outbox/           发送方写这里，一个文件就是一封信
  archive/          投过的信挪到这里（同一封信不会被投第二次）
  returned/         格式不合规/收件人认不出的信挪到这里，旁边附 <名字>.reason.md
  inbox/<窗口id>/   投给这个窗口的信（没有 HTTP 能力的 CLI 直接读这里）
```

## 4. 一封信长什么样

```
来自 codex

给管理员：
这件事要你定方向：口径 A 还是 B。

给 opencode：
我改了 docs/x.md 第 3 段，你接后面那一半。
```

- **第一行必须是 `来自 <窗口 id>`**：文件名不可信（谁都能起名叫 `codex-1.md`），
  而平台**不能**冒充任何人说话；作者由信自己声明，平台验它是已登记的窗口；
- `给<收件人>：` 一行一个块；收件人写**窗口 id**；另有别名 `管理员` / `admin`
  → `AP_ADMIN_SUBJECTS` 里被委托的管理员窗口；
- 块内容是下一个块头之前的全部文字（不做润色，原样转）。

## 5. 投递规则

一个 worker（`python -m app.relay.worker --loop`）扫 `outbox/`，每封信：

1. 收件箱放一份文件：`inbox/<收件人>/<时间>-<原文件名>`，开头一行注明「来自 X（转接于 …）」；
2. 消息面记一条定向消息：**作者是 `relay` 这个已登记的窗口自己**，正文首行写
   「来自 X：」—— 谁说的、谁转的，分得开；界面里因此看得见，`message_deliveries` 照常记录；
3. 信挪进 `archive/`：进程重启也不会重复投。

一份内容两处落地：**人看消息，CLI 读文件**。这是选"文件 + 消息都投"的原因。

## 6. 失败处置（不猜、不兜底）

| 情况 | 处置 |
|---|---|
| 第一行没有 `来自 <窗口 id>` | **整封退回** `returned/`，附原因 |
| 作者不是已登记的窗口 | 整封退回，附原因 |
| 某个块头的收件人不在名册 | 整封退回，原因里列出认不出的名字；**一条都不投** |
| 块内容为空 / 写给发送方自己 | 整封退回（后者防自环） |

退回不是丢掉：信挪进 `returned/`，旁边那份 `.reason.md` 写清为什么没投，改好格式重新
放进 `outbox/` 即可。**不做部分投递**：投了一半，读的人会以为那就是全部。

## 7. 本版不做（写清边界）

- **跳数/线程控制**：要可靠地算跳数，得让收信方回信时带上 thread 引用；在做到之前，
  平台不假装自己知道"这是第几跳"，只挡住自环。登记在这里，不是遗漏；
- 不做重放/补投（归档里有原件，但没有重发机制）；
- 不改 §19 的读权限：定向消息仍然只有两端看得到（谁想让人看见，就把块写给那个人）。

## 8. 开关与验收

- `AP_RELAY_MODE=1` 表示"这台机器上跑转接"，默认关闭；关着时平台行为与今天一致
  （worker 不启动，消息面不解析任何格式）；
- 验收 `tests/test_relay_mode.py`（8 条）：块拆分与 `管理员` 别名、非信封不误判、
  未知收件人/空块/自环整封退回、作者行解析、投递后收件箱与消息各一份且作者是 relay、
  未登记作者退回、投过的信不重复投。
