## P2-7：开工向导「管理员」候选看不到新注册窗口

**缺陷**：页面打开之后才注册的 Harness（E2E 里的 `qoder`）不出现在开工向导的管理员
候选里；名单只剩「网关配置的 ADMIN 身份 + 已有项目成员」，只能改网关 admin token
才能选中，看起来像注册失败。

**根因**：`office/src/main.js` 在模块求值时只读一次 `/api/formal/status`，候选名单
由这份快照 + `project.members` 拼出来。注册发生在页面加载之后，快照里没有；而
`project.members` 是「开工时定下的成员」，不是「平台上现在有哪些窗口」。

**规则**（实现见 `office/src/opening-candidates.js`）：

- 来源：平台注册表 `/api/formal/status` → `harnesses`，**每次打开向导前现读**；
  不使用页面加载快照，也不使用 `project.members`。
- 保留条件（全部满足）：
  1. `registration_version` 非空（注册出来的窗口，不是网关适配器模板）；
  2. `capabilities` 含 `coding`（管理员要能跑细化 CLI）；
  3. `credential_count` 不为 0（没有平台凭据就细化不了，派单会永远停在 ready；
     字段缺失按有凭据处理，兼容旧载荷）；
  4. 不是平台助手 `office-admin`（模型身份，不是外部窗口）。
- `-admin` 结尾 / 名字含「管理员」的外部窗口**保留**（成员候选那边才排除它们）。
- 离线窗口保留在名单里：人需要看见它现在不在，而不是让它凭空消失。

**验收**：`node office/scripts/verify-opening-admin-candidates.mjs`
（自带静态服务器 + 拦截 API，不连平台）

- 首屏注册表没有 `qoder`，点「开工配置」前注册表多出 `qoder` → 候选里必须出现
  `qoder`，且显示名来自注册表（不是裸 id）；
- 平台助手、无凭据、无 `coding`、无 `registration_version` 四类样本必须不出现；
- `project.members` 里那个已不在注册表的旧成员必须不出现（证明没有退回成员名单）。

## P2-8：「批准，开始做」被「与管理员对话」模态拦截

**缺陷**：人工走查时，运维抽屉里的「批准，开始做」连续 15 次被「与管理员对话」的
模态层拦截（Playwright 报 `intercepts pointer events`），只能改 DOM 直点。

**根因**：`office/src/flat-office.js` 用 `showModal()` 打开对话面板，`<dialog>` 进入
top layer 后整页进入 inert，抽屉里的按钮不可命中。

**改法**：只改层级，不改按钮位置与命中区域。

- `flat-office.js`：对话面板改用 `show()`（非模态），不再把页面推进 inert；
- `flat-office.css`：`.flat-admin-chat[open]` 显式 `position: fixed; inset: 0;
  margin: auto; z-index: 45`。非模态 `<dialog>` 不自动居中，不加这条会掉到页面末尾。
  45 高于顶栏（40）、低于终端面板（60）。
- 真正的模态（决策确认、目录选择等）不动。

**验收**：`node office/scripts/verify-office-approve-behind-chat.mjs`

- 打开「与管理员对话」，断言 `#flatAdminChat` 的 `:modal` 为 `false`；
- 面板开着时用 **Playwright 默认的真实点击**（带可命中性检查，不是 `force`）
  点运维抽屉的 `[data-act="approve-plan"]`，断言请求真的打到 `/plan/approve`；
- 批准后对话面板仍开着（没有为了点按钮被迫关掉）。
